### 3) Позитивные наблюдения

- **Exhaustive seam компилируется.** `JujutsuCharacters:30-37` и `JujutsuCharacterClients:26-33` — оба `switch` без `default`. Добавление `JujutsuCharacter` падает компиляцией ровно в двух местах — гарантия сильнее чем карта+тест. Поля `*_DEFINITION` с суффиксом делают transposition visually wrong (`case NOBARA -> TODO_DEFINITION`). `CharacterDefinitionRegistryTest:85-91` `assertEveryVesselResolves` закрывает второй half Gap (`case TODO -> NOBARA_DEFINITION` компилируется — runtime self-check `id()` ловит).

- **Derived sweeps, не hand-lists.** `JujutsuCharacters.all():49-56` и `JujutsuCharacterClients.all():39-46` оба `JujutsuCharacter.values()` → `definition()`. Невозможно забыть vessel в sweep при добавлении в switch. `assertTheSweepMatchesTheSwitch:94-103` и `assertEveryVesselIsBound:55-56` дублируют это property-based.

- **Разделение интерфейсов мотивировано dedicated server.** `CharacterDefinition` javadoc `No client types may appear here, ever.` — не стиль, а crash-at-load на dedicated. Физическое разделение source sets (`src/main` vs `src/client`) шире чем просто два интерфейса. Whole-tree guard `CharacterClientRegistryTest:63-73` сканирует весь `src/main`, а не только definitions.

- **Регистрация один раз, declared once, распределённая.** Каждый vessel владеет ровно семью осями в `CharacterClientDefinition`: `rosterEntry` (включая `portrait`/`portraitIsSkin`/`abilities`), `playerSkin` (одна `SKIN` константа — читается roster и `CharacterSkinMixin` — раньше дублировалась), `skinAnimation`, `accent/warmth`, `bodyScale` (delegated to enum), `registerClientHooks`, `moduleName/Description/StarterEnabled`, `hudSlots/maxCooldownTicks`. Server symmetric: `id/tryCast/registerServerHooks/applyAttributes/removeAttributes/adjustIncomingStaggerTicks/selectCurseLink/onSelected/onDeselected`. Нигде нет второй копии `SKIN` или ростер → HUD расхождения — `HudSlot` строится из `rosterEntry().abilities()` (`hudSlot(strip,index,ability)`): `icon/nameKey` — один источник.

- **Server-authoritative диспетчер чистый.** `CharacterAbilityExecutor:15-35` владеет ровно двумя shared checks (`NONE` + `isReady`), затем `definition.tryCast`. Vessel-specific `stagger gate` и `fallback message` живут в `NobaraAbilityRouter` — правильное место per `Vessel-definitions.md:28-29` и `KNOWN_ISSUES.md:246-263` (E10/E11). Router exhaustive без `default` — новый `CharacterAbility` падает compilation в каждом роутере.

- **Lifecycle order верный и documented.** `CharacterSelectionManager.select:14-30` — `onDeselected(prev)` **до** `setAttached`, `applyForSelection` sweep, `onSelected(arriving)` **после**. `applyForSelection` (`CharacterCombatModifiers`) sweep `removeAttributes` для **всех** vessels then `applyAttributes(selected)` — не нужно clearance known set, `remove what you add` контракт в одном файле per vessel.

- **VFX Core правильно wired на seam.** `JujutsuModClient:25` `VfxDirector.initialize()` **до** `29` `registerAll()`.
