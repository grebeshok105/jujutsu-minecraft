### 3) Позитивные наблюдения

- **Preflight атомарен и per-body строг.** `TodoSwapPlan.preflight(null→empty)` и `TodoTripleSwapPlan.preflight` требуют всех дестинаций non-null; `TodoBoogieWoogieRuntime.tryCast:86-91` отдаёт `SOFT` только Todo, `STRICT` цели; `PairSwap.commit:146-149` и `tripleCast:237-241` — `STRICT×2`/`STRICT×3`; `StoneRuntime:137-138,207-208` — `STRICT`. Нет default-overload `findSafeDestination` — каждая точка вызова явно называет strictness (`BoogieWoogieRuntime.java:139-143` — deliberate deletion of overload). Это закрывает регресс первого слайса, когда цель ставилась через unchecked fallback.
- **`consume` един и liveness-guarded.** `TodoSwapMomentumRuntime.consume:117-128` — единственная точка списания для `AFTER_DAMAGE` и `AFTER_KILLED_OTHER_ENTITY`; `target.isAlive()` guard предотвращает `CombatStagger` на мёртвом теле и запись в `GLOBAL` по UUID трупа; `applyStagger=false` для kill-ветки — нет стаггера трупу.
- **Re-entrant Black Flash не крадёт окно.** `TodoSwapMomentum.decide:36-38` + `BlackFlashStrike.isApplyingBonus:25-27` + `APPLYING_BONUS` ThreadLocal-подобный Set — `reentrantBonus==true → IGNORE`, окно не списывается на вложенном `hurtServer` бонус-хите. Направление цикла triple зафиксировано и тест-пинится (`TodoTripleSwapPlan:12`).
- **`ADD_MULTIPLIED_TOTAL` выбран верно.** `JujutsuEffects.java:31-35` — `SWAP_MOMENTUM_DAMAGE_MULTIPLIER-1.0` как `ADD_MULTIPLIED_TOTAL` даёт `1.50×1.25`; javadoc явно отметает `ADD_MULTIPLIED_BASE`. Эффект `BENEFICIAL`, 24т, amplifier 0 — ре-грант рефрешит, не стакает (`grant:48-60`).
- **Rollback per-route с логированием.** `BoogieWoogieRuntime.rollback:204-219` — единый метод для 4 путей, `second==null` short-circuit, `firstRestored && secondRestored` иначе `LOGGER.error` с `caster/first/second/restored`. `PairSwap.rollbackTriple:293-305` — reverse-order restore `placed.size()-1 → 0` с per-body `error` + финальный `error` с `moved/destinations`. `StoneRuntime` тоже через `rollback(..., null, null)` — best-effort, но залогирован.
- **`hurtMarked` для сохранения импульса.** `restoreMotionAndRotation:232-243` — `forceSetRotation`/`setYHeadRot`/`setDeltaMovement`/`resetFallDistance` + `hurtMarked=true` чтобы `ServerEntity#sendChanges → broadcastAndSend → ClientboundSetEntityMotionPacket` дошёл до трекеров и до самого `ServerPlayer`. Тот же примитив, что `CombatStagger` — починено для всех путей разом, включая rollback.
- **Shared gate без дублирования.** `TodoSwapGates.evaluate(todo)` читается и real swap и feint (`BoogieWoogieRuntime:48`, `FakeClapRuntime:32`, `PairSwap.tripleCast:184`) — одна truth table для `HANDS_FULL` vs `ALLOWED`. `FakeClapRuntime` не резолвит цель и не аллоцирует `Snapshot` — чистый feint.
- **`SafeBodyPlacement` аллокационно экономен.** `Policy` прекомпилирует `horizontalOffsets` (`buildHorizontalOffsets:103-121` — centre + 4×0.5 + 4×1.0 + 4×diag 0.7, `List.copyOf`), скан `for up=0..3, for offset` — 52 кандидата max, per-body; triple 156 `noBlockCollision` чеков — приемлемо. `boundingBoxAt` использует `body.getDimensions(body.getPose())` — хитбокс соответствует позе.
- **Cooldown только после успеха.** `CharacterAbilityCooldowns.start` + `JujutsuNetworking.sendAbilityCooldown` стоят после последнего `return false` (`BoogieWoogieRuntime:109-110`, `PairSwap:168-170,273-275`, `Stone:161-162,229-230`) — фейл префлайта/коммита не стартует кулдаун; `FakeClap` имеет свой слот `PRIMARY_SNEAK` 20т, не тратящий `PRIMARY` 60т.
- **Effect-таблица делегирует kill-путь.** `TodoSwapMomentum.decideOnKill:64-72` не копирует три проверки, а вызывает `decide(false, 1.0f, ...)` — `blocked=false`/`DAMAGE_LANDED=1.0f` форсятся, т.к. `AFTER_DAMAGE` не фаерится на убийство; `directIsOwner` читается из `victim.getLastDamageSource().getDirectEntity()` — стрела Todo имеет `directEntity==Arrow`, не спишет melee-окно.
