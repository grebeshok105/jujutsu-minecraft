### 3) Позитивные наблюдения

- **Единая точка истины**: `TodoBoogieWoogieRuntime.findSafeDestination:161-164` делегирует в `SafeBodyPlacement.find` — нет копипасты логики между Todo и Megumi. `Policy` с `upwardBlocks/borderMargin/exactRequestedFallback` и предвычисленным `horizontalOffsets:38-44` — аллокаций на каст нет (`List.copyOf:120`), политики `static final` в обоих профилях.
- **STRICT/SOFT per-body, не per-cast** — ключевой фикс из `KNOWN_ISSUES.md:35` соблюдён: `TodoBoogieWoogieRuntime.java:86-88` (Todo `SOFT`, target `STRICT`), `TodoPairSwapRuntime.java:146-149,237-241` (pair 2×`STRICT`, triple 3×`STRICT`), `TodoStoneRuntime.java:137-138,207-208` везде `STRICT` для bystander и для самого Todo у камня. Удаление defaulting overload (`TodoBoogieWoogieRuntime.java:139-143` комментарий) предотвращает тихую подмену `SOFT` для чужого тела. Сверено `grep STRICT` — 7 вызовов, 1×SOFT.
- **World bounds + chunk load + border margin 0.05 (inflate AABB) + solid collision — полный набор**: `SafeBodyPlacement.isInWorld:87-93` проверяет `hasFinitePosition && isInWorldBounds && hasChunk && isWithinBounds(boundingBoxAt.inflate(borderMargin))`, `isPlaceable:82-85` добавляет `noBlockCollision(body, boundingBoxAt)`. Bounding box берётся из `body.getDimensions(body.getPose()).makeBoundingBox(candidate):95-97` — поза учитывается (crawl/elytra), размер тела реальный, а не константа.
- **Border margin корректен**: `0.05` и `inflate(borderMargin)` на `AABB`, не на `BlockPos` — краевой кейс на 0.05 блока от границы ловится до телепорта. Значение едино в обоих `Profile` и совпадает с `AGENTS.md:86` и `Codex Todo-Boogie-Woogie.md:20`. `isWithinBounds` проверяет весь inflated `AABB`, не центр.
- **Air/water валидность by design сохранена**: только `noBlockCollision`, без `isSolidFloor`/`isOnGround`/`entity occupancy` — вода, воздух, полёт, crawl валидны, как требует `AGENTS.md:92` и `SafeBodyPlacement.java:15-19`. `noBlockCollision` в воде возвращает `true` (вода без collision shape), crawl `Pose` даёт низкий `AABB` и тоже проходит.
- **Void handling для камня явный**: `TodoStoneEntity.java:88-119` — `getY() < level.getMinY():96` → `endFlight`, `ProjectileUtil` ray + `move(SELF)` + `horizontalCollision|verticalCollision|velocity<1e-8`, `canUsePortal()=false:156-160`, `fireImmune:151`, `noSave` — камень не зависнет как immortal ghost при void/expiry/collision/cleanup. `SafeBodyPlacement` void прикрыт через `isInWorldBounds` (Y-range).

### 4) Вердикт

**PASS WITH CAVEATS**

Срез реализует заявленный контракт точно: `world bounds + chunk load + world border margin 0.05 (inflate AABB) + solid collision (noBlockCollision + boundingBoxAt по позе)`, радиус `1.0` + `3` вверх (13 точек диска × 4 высоты = до 52 кандидата на тело), без floor/occupancy gate осознанно, air/water валидны, void для камня покрыт отдельным `getY() < minY`, `STRICT`/`SOFT` разведены per-body.
