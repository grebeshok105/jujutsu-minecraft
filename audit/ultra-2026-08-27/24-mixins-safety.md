### 3) Позитивные наблюдения

- **Обоснование необходимости mixin безупречно:** каждый из 7 миксинов решает задачу без Fabric API альтернативы. `getDimensions`/`getSkin`/`extractRenderState`/`Camera.setup`/`getFov`/`renderHandsWithItems`/`LivingEntityRenderer.render` — Fabric не предоставляет событий. `VfxDirector` уже использует `HudElementRegistry.replaceElement` вместо HUD mixin — пример правильного `prefer API`. Единственный потенциальный API-кандидат — `Attributes.SCALE` для bodyScale — сознательно не использован (mixin проще и детерминирован, scale enum константный).
- **WrapOperation/WrapMethod вместо Redirect:** единственный Wrap — `CharacterSkinAnimationMixin:63 @WrapMethod` — корректный выбор (оборачивает весь метод с `try/finally` и `PoseStack` guard). Остальные — `@Inject` с `cancellable` там где нужен override (`getDimensions`, `getSkin`, `getFov`). `@Redirect` отсутствует полностью — **best practice**.
- **@Unique дисциплина:** все синтетические поля/методы с префиксом `jujutsumod$` и аннотацией `@Unique` (`FirstPersonHandFxMixin:30-37,102,129,184`, `CharacterSkinAnimationMixin:32,113,117`). Нет конфликтов нейминга с vanilla полями. `@Shadow` только на существующие vanilla поля/методы (`LivingEntityRenderer.model`, `Camera.setRotation/setPosition/getXRot/getYRot/getPosition`, `ItemInHandRenderer.renderPlayerArm`).
- **Узкий scope где возможно:** `CharacterSkinMixin` на `AbstractClientPlayer` (не `LivingEntity`), `PlayerRenderContextMixin` на `PlayerRenderer` (не `LivingEntityRenderer`), `HairpinGameRendererMixin` только `getFov` — минимальная поверхность. `HairpinCameraMixin` — только `setup` TAIL, без INVOKE filter лишнего.
- **Fail-open безопасности:** `HiddenBodyRenderGate` и `ShadowBodySink` используют `ConcurrentHashMap` + TTL + lazy expiry — потерянный `VfxCue` пакет приводит к видимому телу, а не к вечной невидимости. `CharacterSkinAnimationMixin:70-78` гарантирует что скрытое тело не оставляет `CharacterSkinAnimationState` утечки (`stale.close()` в early return + `finally` в WrapMethod).
- **Server/client разделение:** `CharacterPlayerDimensionsMixin` в `src/main` корректно работает через `CharacterSelectionView` (server — `DataAttachment`, client — `Function<UUID,JujutsuCharacter>` injected из `JujutsuModClient`). Остальные 6 миксинов — в `src/client` и никогда не грузятся на dedicated server (проверено `loom.splitEnvironmentSourceSets` + `fabric.mod.json:environment:client`). `CharacterSkinAnimationMixin` vessel-neutral — делегирует в `CharacterSkinAnimationRenderer` → `JujutsuCharacterClients.definition().skinAnimation()`.
