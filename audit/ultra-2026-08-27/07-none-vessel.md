### 3) Позитивные наблюдения

- **Vessel Seam выдержан идеально.** `JujutsuCharacter.java:34-42 byId` + `JujutsuCharacters.java:30-37` и `JujutsuCharacterClients.java:26-32` — оба exhaustive `switch` без `default`. `NoneDefinition` и `NoneClientDefinition` — единственные правки для добавления `NONE`, shared файлы не трогались кроме enum. `JujutsuMod.java:44-46` и `JujutsuModClient.java:29` лупят `all()` — `NONE` автоматически попал в `registerServerHooks()` (no-op) и `registerAll()` (no-op) без ручного списка. `CharacterAbilityExecutor.java:17-23` и `CharacterCombatModifiers.java:29-33` не знают про `NONE` кроме `NONE`-gate — это отсутствие vessel, а не vessel, по контракту `AGENTS.md:219-238` и `Vessel-definitions.md`.
- **Null-object вместо `null`.** `NoneDefinition.java:13-25` — полноценный `CharacterDefinition` с `tryCast → UNHANDLED_FAILURE` + унаследованные no-op `removeAttributes/onSelected/onDeselected`. Shared код всегда получает definition через `JujutsuCharacters.definition(selected)` — нет `if(defined==null)` ветвлений. `NoneClientDefinition.java:13-56` аналогично — карта `BUST` emoji, `false` для `portraitIsSkin`, `List.of()` abilities — реальная карточка в меню, не `null`.
- **Server-authoritative выбор.** `SelectCharacterPayload.java:16/20` `readUtf(32)/writeUtf(*,32)` bounded; `JujutsuNetworking.java:32-33` `server.execute(() -> select(...))` — main thread only; персистентность через Fabric Data Attachment `JujutsuAttachments.java:12 .persistent(CODEC).copyOnDeath()` — переживает смерть и рестарт уровня, `CHARACTER_STATE.DEFAULT = (NONE, emptySet)` совпадает с `ClientCharacterSelectionManager.java:76-78 characterOrNone fallback`. `syncOnJoin` обменивает `NONE` корректно (`"none","wide"`).
- **Idempotent starter kit без дубликатов.** `NobaraDefinition.onSelected:56-59` вызывает `ProjectJjkNobaraLoadout.ensureStarterTools` на **каждый** `select`, включая re-select `NOBARA`. `ProjectJjkNobaraLoadout.java:12-23` честно idempotent: `hasHammer/hasDoll/countNails` сканирует `getContainerSize()` + `giveOrDrop` с `add`/`drop` fallback. Переключение `NONE→NOBARA→NONE→NOBARA` не дублирует молот/куклу/гвозди, потерянный kit восстанавливается, `NONE` не получает kit (только `NOBARA` оверрайдит `onSelected`). Это именно то что `AGENTS.md:49` и `KNOWN_ISSUES.md:E12` называют "re-applied on every selection".
- **Отсутствие утечек.** `NoneDefinition` не владеет entity, эффектом, VFX, `HashMap`-state — `onDeselected` no-op корректен (нечего чистить). `TodoDefinition.onDeselected`/`MegumiDefinition.onDeselected` чистят своё, `NONE` не мешает. `CharacterCombatModifiers.applyForSelection` sweep `for(all) remove` удаляет `Todo` модификаторы при `select(NONE)` — игрок возвращается к vanilla `ATTACK_DAMAGE/ATTACK_SPEED`. `AbilityHud.java:72-75` `NONE` → `clearStripBounds` + `return` — нет рендера, `VfxDirector.cancelFirstPerson()` в `ClientCharacterSelectionManager:47-49` отменяет first-person анимацию при `NOBARA→NONE`.

### 4) Вердикт

**PASS WITH CAVEATS**

`NONE` как Null-object реализован образцово: seam не нарушен, shared код не ветвит по vessel, сервер-авторитетность и Fabric Data Attachment персистентность (включая `copyOnDeath`) работают, idempotent kit без утечек, отсутствие `onDeselected`/`registerServerHooks`/`VFX` для `NONE` — именно no-op что нужен, HUD/ростер/тема отображаются корректно (слейт акцент, последний в меню, пустой ability strip).

Caveats — 3 границы где `NONE`-специфика усиливает общие слабые места, и 5 minor эрозий hyperbolic для следующего vessel-а:

- **Дефекты данных:** `claimStarter(NONE)` засоряет persisted `Set<String>` мёртвым `"none"` (major, дёшево чинить).
- **Fail-open wire:** `byId` unknown → `NONE` без лога позволяет silent deselect и скрывает typo/версионный десинх (major).
