## Сводка

Интеграционный PR (#115 быстрый селектор шикигами + #116 проклятые инциденты + #117 автономная стая и партиальные манифестации): +28k/−789, ~360 файлов, три новые подсистемы с общими швами (удержание, перцепция, кулдауны, ввод). **Риск: Medium** — блокеров-крашеров нет, но пять реальных major-проблем на краевых путях (смена измерения, выгруженные чанки) и два системных долга.

## Сильные стороны

- **Vessel-шов выдержан чисто**: `selectShikigami`/`onDeselected`/`hasQuickSelector`/`openQuickSelector` — default-методы на `CharacterDefinition`/`CharacterClientDefinition`, shared-код ни разу не спрашивает «кто этот игрок», пейлоады vessel-нейтральны, все роутеры получили исчерпывающие ветки для `PARTIAL`/`PARTIAL_RELEASE`.
- **Перцепция стыкована правильно**: `CursePerception` расширен через `IncidentPerceptionBridge`, а не разветвлён — немаг в критической зоне видит и может бить духов, клиентское зеркало дублирует тот же закон.
- **Состояние синкается дисциплинированно**: отклонённый клик по селектору всегда отвечает авторитетным снапшотом (исправление оптимистичной отметки), пуш состояния на смену сосуда/реконнект, heartbeat-зоны с TTL на клиенте, dead-reckoning геометрии по ключу зоны.
- **Мир сохраняется надёжно**: `IncidentSavedData` роняет испорченные записи по одной, Dirty-map, клэмпы переполнения давления; `pendingDeltas`/`PENDING_DRAIN` — продуманная очередь отложенной записи.
- **Ввод**: `SelectorGesture` — чистый автомат tap/hold, фикс `isDefault()` для незабинденных клавиш, суб-тик клики шлют оба фронта.
- Новые миксины узкие и каждый оправдан отсутствием Fabric-события (push-подавление, dismount-гейт, travel-инжект, render-стейт).

## Проблемы

1. **[major] Кросс-измерение у dwell-релокации** — `IncidentControl.syncDwellCenter` двигает `record.center`, но не `record.dimension`; `DwellProvider` в принципе не несёт измерения (inline `IncidentControl.java`). Затронут и `InfectionSink.scanKnownContainers` (inline `InfectionSink.java`) — позиции контейнеров без dim сканируются на уровне зоны и без `hasChunk`-гварда.
2. **[major] Язык жабы читает блок каждый тик без `hasChunk`** и без предела троса (inline `MegumiPartialRuntime.java`) — телепорт владельца оставляет якорь в выгруженном чанке, сервер грузит его синхронно каждый тик.
3. **[major] Десинк перцепции на смене измерения** — `OVERRIDES` шлёт только на флип, клиент чистит зеркало на `AFTER_CLIENT_WORLD_CHANGE`; true→true через портал оставляет клиента в `false` навсегда (inline `PerceptionOverrideRuntime.java`).
4. **[major] `MegumiPackCoordinator.assign` не амортизирован** — `hasLineOfSight` на каждую пару тело×кандидат каждый тик; амортизация есть только у скана контекста (inline `MegumiPackCoordinator.java`).
5. **[minor] Дублированные политики/математика**: `SealPolicy.requiredTier` ≡ `TemplateRollPolicy.sealDifficulty` (inline `SealPolicy.java`), `sealBand()` ≡ серверный `degradationBand` (inline `IncidentZoneState.java`).
6. **[nit] Мёртвый код**: `IncidentRuntime.isActive` не вызывается (inline).
7. **[nit] Аллокации в горячем рендере**: `IncidentZoneRenderer.spawnMotes` создаёт `RandomSource` и собирает строковые ключи геометрии каждый кадр — ограничено бюджетом, но мусорит.

## Архитектурные риски на будущее

- **`DwellProvider` — позиции без измерения**: интерфейс сегодня возвращает голый `BlockPos` везде (`dwellCenterOf`, `containerOf`, `knownContainerPositions`, `noteContainer`). Это не локальный баг, а форма контракта: каждая следующая фича, опирающаяся на dwell (доставка лута, следы, погоня), унаследует кросс-dim путаницу. Стоит исправить контракт один раз — `record.dimension` + `Set<DimensionedPos>` — пока вызовов мало.
- **Неограниченный рост `IncidentSavedData`**: `incidents`/`knownObjects`/`voidedObjects` только пополняются — зарубцевавшиеся (scarred) записи без самоподдерживающихся узлов так и лежат в карте, а `recordsForRuntime()`, `isRecordObject`, `durableInstanceCount` сканируют её целиком. За жизнь мира с давлением-спавнером файл растёт вечно, а каждый `registerInstance` — O(все исторические записи). Нужен TTL/эвикт полностью мёртвых записей.
- **Статические singleton-рунтаймы с `ConcurrentHashMap` везде** (TRACKED, PACKS, OVERRIDES, PARTIALS, CONTEXTS, HELD): принято в кодбейсе и вылизано хуки-очистками, но уже 6+ реестров на владельца — следующая фича с общим «registry + SERVER_STOPPING + DISCONNECT» шаблоном просит общий owner-scoped каркас, иначе каждый новый runtime будет изобретать свои утечки.
- **Клиент-серверная дублирование политики** (seal band, тир-матрица, часть профилей): появление третьей копии — вопрос времени; данные политик стоит гнать в пейлоадах, а не пересчитывать.
