## Сводка

Батч пост-мерж фиксов по `audit/review-3pr`: синк нокбэка слэма/дэша, очистка кислотных зон на остановке сервера, валидация пула способностей, RELEASE по таймауту, source-aware броня, гейт страха на игроков, settle/give-up у шелтер-цели, сужение биом-селектора спавна, удаление мёртвого record, тесты. **Риск: Medium** — каждый подключённый фикс корректен и бьёт в первопричину, но два «флагманских» изменения (обход брони хазардами, гейт пула по грейду) на момент мержа в проде не вызываются, а отчёт с отложенными правками callsite'ов в репозиторий не закоммичен.

## Сильные стороны

- `hurtMarked = true` — правильный ванильный механизм: движение `ServerPlayer` клиент-авторитетно, и флаг синка скорости выставлен после обеих веток push (включая вертикальный подброс) — фикс именно в корне, не workaround.
- `SERVER_STOPPING → ZONES.clear()` — корректно закрывает утечку статического рантайма между мирами одной JVM.
- `CursedSpiritShelterGoal`: таймаут проверяется до `isDone()` («вечно in-progress» путь тоже сдаётся), `stop()` армает кулдаун сканирования, все магические числа уехали в `CursedSpiritShelterPolicy` по конвенции, `selfScore` кэширован — пер-тиковых тяжёлых запросов нет.
- Биом-селектор — чистый публичный API (`excludeByKey` + теги `IS_OCEAN`/`IS_RIVER`), сужение ровно по ванильному монстр-листу.
- `peacefulRefusesEndToEndThroughCheckSpawnRules` — отличный оракул: прокси, бросающий на любом методе кроме `getDifficulty`, пинит не только конъюнкт, но и его приоритет в `checkSpawnRules`.
- Гейт `target instanceof Player` у страха одинаковой формы в `inRange` и `applyTo` — согласовано с GRAB_RUNNER.
- `expireWindow` для GRAB_RUNNER остался корректным: `RunnerEffect.end` сам дёргает `forceEnd` (идемпотентно), `state == null` безопасен.

## Проблемы

1. **[blocker → inline ArmorEffect]** 4-аргументный `absorb` на момент мержа мёртв: `hurtServer` (`CursedSpiritEntity`) зовёт старый трёхаргументный вызов — BYPASSES_ARMOR в игре не работает, хотя «Для игрока» обещает обратное. Тест пинит шов, а не интеграцию.
2. **[major → inline brain]** `loadFrom(input, grade)` тоже не вызывается в проде — сущность грузит одноаргументный `loadFrom(input)`: гейт `eligible` не срабатывает ни разу.
3. **[major → inline brain]** RELEASE теперь покрывает только таймаут; ранние выходы — `DashEffect.tick` (`forceEnd` при потере перцепции) и `RunnerEffect.tick` (victim-loss/disconnect/perception через `end()`) — клип по-прежнему оставляют висеть, и это самые частые пути завершения.
4. **[minor → inline ShelterGoal]** `selfScore`-кэш протухает при откате `getGameTime()` назад (`/time set`) — `now - cachedAt` уходит в минус.
5. В `expireWindow` при `state == null` (id уже снят своим тиков через `forceEnd` + RELEASE, как у dash/slam после хита) бродкастится второй RELEASE — безвредно, но лишний пакет на хит. Там же `instanceof ServerLevel` — мёртвая защита: метод private и вызывается только из `tick`, где `level` уже `ServerLevel` (можно протащить параметром).
6. Новые ветки give-up шелтера (`MAX_NAV_FAILURES`, `NAV_TIMEOUT_TICKS`) не имеют оракула — `CursedSpiritShelterGameTests` пинит только happy-path settle; регрессия в give-up уйдёт незамеченной.
7. Тело PR ссылается на `audit/review-3pr/fix-abilities.md`, но этот файл никогда не был закоммичен (`git ls-tree` пуст, `git log --follow` молчит) — отложенные правки callsite'ов существовали только в нём. Это прямое нарушение §12 AGENTS.md («ничего task-related не живёт только на локальной машине»).

## Архитектурные риски на будущее

- **Паттерн «шов есть — callsite отложен»** — главный риск этого диффа. Оверлоад + тест на шов при старом production-вызове даёт зелёный `qualityGate` и ложные обещания в «Для игрока». Для audit→fix пайплайна это системная дыра: фикс считается сделанным, хотя игрок его не видит. Правило: поведенческий фикс не считается закрытым, пока callsite не переключён в том же PR, либо заведён issue с явным списком остатка.
- **Владение attack-клипом размазано по коду**: WINDUP бродкастит каждый эффект на старте, RELEASE — dash/slam на хите, brain на таймауте, никто на ранних выходах. Любая новая clip-способность обязана помнить про все пути завершения — уже дало дыру. Поднять владение в brain: единая точка `closeWindow(id)`, где снятие окна любой природы (таймаут, forceEnd, end) для `occupiesAttackClip`-id бродкастит RELEASE — закроет все пути разом вместо whack-a-mole.
- **Статический рантайм-стейт по соседству**: `ZONES` теперь очищается на `SERVER_STOPPING`, а `RunnerEffect.CARRIED` (тот же `ConcurrentHashMap`-сет, UUID игроков переживают смену мира в одной JVM) — нет. Тот же класс утечки, починенный здесь выборочно. Стоит аудит всех static-структур `cursedspirit` (включая `HoldSupport`-маркеры) на сервер-стоп.
- **Отложенная работа не должна жить в незакоммиченных файлах**: см. проблему 7 — если отчёт остался на машине воркера, маршрут для следующего агента теряется.
