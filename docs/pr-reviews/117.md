## Сводка

Один большой PR на две связанные фичи Мегуми: (1) сосуществование стай (issue #107) — пачки по типам, per-type кулдауны призыва, глобальный sic с отменой по промаху, автономный координатор целей; (2) частичные проявления (issue #108) — крылья Нуэ и язык жабы через новый слот PARTIAL / PARTIAL_RELEASE. +6542/−532 по 79 файлам, ~3800 строк новых тестов.

**Риск: Medium** — код в основном аккуратный, швы архитектуры соблюдены, покрытие тестами сильное; но есть два реальных бага в новых механиках (якорь языка на несолидных коллидируемых блоках и сирота-маркер после нештатного дисконнекта) и один горячий путь с O(тела×кандидаты) рейкастами каждый тик.

## Сильные стороны

- **Шов сосуда выдержан безупречно.** PARTIAL(10)/PARTIAL_RELEASE(11) добавлены append-only в wire-формат, роутеры Nobara и Todo отвечают явными отказными ветками вместо default, `WireFormatTest`/`NobaraAbilitySlotsTest` запинили новые id и новый формат мульти-лейбловых веток — следующий сосуд получит слот бесплатно, а парсер-правила не сломаются.
- **Правило «нет миксинов без нужды» соблюдено образцово.** Крылья целиком на Fabric-событиях: `EntityElytraEvents.CUSTOM` с развёрнутым объяснением, почему не `ALLOW` (тот вето-семантикой глушил бы ванильную элитру всех игроков). Единственный новый миксин `TonguePhysicsMixin` узкий, с javap-обоснованием выбора точки (Player.travel @TAIL, а не LocalPlayer), guard `instanceof LocalPlayer` и вырезом под GRIPPED.
- **Правильное разделение pure/рантайм.** `MegumiCoordinationPolicy`, `MegumiShikigamiSwapPolicy`, `TonguePullPolicy`, `MegumiFailureMemory` — чистые классы, гонимые JUnit; магические константы собраны в профилях; `TonguePullPolicy` осознанно живёт в shared-пакете, потому что mixin-пакет не может называть типы сосуда — прецедент HoldSupport назван прямо.
- **Краевые случаи проработаны.** Same-tick duplicate guard в tryPrimary, отказные ветки до message-fallback (PARTIAL у Nobara уходит молча до «no target»), teardown собирает все выходы в одну точку, cooldown перенесён на per-type мапу с документированным обоснованием отсутствия DESELECTED-цены (issue #84), fixture-reset и mcpdev-снапшот обновлены синхронно.
- **Тесты не декоративные.** ~13 GameTest-ов на одну только автономию (дистрибуция толпы, стабильность меток, приоритет агрессора владельца, failure memory пыжа), плюс коэкзистенс, координация, партал-наборы и JUnit-пины политик; `KNOWN_ISSUES.md` честно зафиксировал оба сдвига семантики (глобальный sic с PRIMARY_SNEAK-ценой и clear-on-miss).

## Проблемы

1. **[major]** `MegumiPartialRuntime.tickTongue`: предикат `isSolid()` не совпадает с `ClipContext.Block.COLLIDER`, которым якорь выбирался — заборы, панели, плиты, ступени, стены являются валидными якорями, но язык отцепляется от них уже на следующий тик (инлайн-комментарий).
2. **[major]** Маркер частичной формы — `MobEffectInstance` с `INFINITE_DURATION`, то есть сериализуется в NBT игрока, тогда как `PARTIALS` живёт в памяти. Краш между автосейвом и дисконнектом (или дисконнект, когда игрок уже вынут из списка) оставляет сироту: вечный глайд + иммунитет к падению без записи в мапе, и `tick` её никогда не увидит — reconcile-точки на входе нет (инлайн-комментарий).
3. **[major]** `MegumiPackCoordinator.assign` вызывает `body.hasLineOfSight(candidate)` для каждой пары «тело × кандидат» **каждый тик** — пятитиковый кэш амортизирует только entity-скан, матрица LOS считается живьём каждый тик (инлайн-комментарий).
4. **[minor]** `contextFor` может построить контекст из мозга посреди entity-тика — до того, как reconcile/retaliate этого тика осели; плюс `rebuild` повторно прогоняет `markHolders`, уже собранный в `tick` (инлайн-комментарий).
5. **[minor]** `MegumiShikigamiSwapPolicy.decide`: ветка `selected == DOGS` и параметр `dogActive` на проде недостижимы — `tryPrimary` перехватывает DOGS до вызова `decide` (инлайн-комментарий).
6. **[nit]** `MegumiRabbitsBrain.dropUpkeepWithoutPack` чистит по `packs(ownerId).isEmpty()` — метка кроликов теперь переживает свою пачку, пока жив любой другой тип; безвредно из-за привязки к `summonToken`, но окно жизни расплылось (инлайн-комментарий).
7. **[nit]** Висячий javadoc в конце `MegumiShikigamiProfile` (константа физически живёт в `MegumiProfile`) и потерянный перевод строки в конце файла (инлайн-комментарий).
8. **[nit]** Мёртвый lang-ключ `message.jujutsumod.megumi.shikigami.swap` в обоих языках — ветка свопа удалена, ключ и формат `%s` остались (инлайн-комментарий).

Без инлайна: `Map.copyOf(PARTIALS)` аллоцирует каждый тик (тривиально); relog обнуляет per-type кулдауны — соответствует старой семантике shared-slot, но лёгкий «выйди-зайди» обход цены призыва теперь встроен в дизайн; payload языка без owner-uuid корректен, пока он owner-only (см. ниже).

## Архитектурные риски на будущее

- **Instanceof-башни координатора.** `markOf` / `markKindOf` / `acceptsMark` / `assignAutonomous` / `clearMarkOf` — пять параллельных разборов «сикигами или собака». Пока семейств два — терпимо, но это ровно тот шаблон, который скопирует следующий владелец петов. Интерфейс вида `MegumiMarkCarrier` (sicTargetUuid / markKind / acceptsMark / assignAutonomous / clearMark) снял бы весь класс дублирования разом.
- **Расщеплённая authority маркер ↔ мапа.** Маркер партала персистентен (NBT), `PARTIALS` — нет: это латентный класс бага для любого следующего партала или эффекта-флага. Просится общий reconcile-seam на JOIN (маркер есть, записи нет → снять / восстановить).
- **Per-owner контексты + горячий тик.** `CONTEXTS` по владельцам плюс per-tick скоринг масштабируются линейно по игрокам и квадратично по телам×кандидатам. На целевые 1–2 игрока — нормально; если такой координатор появится у второго сосуда, общий combat-context сервис окупится.
- **Эксклюзия «тип занят» размазана.** Партал блокирует призыв, цикл выбора и обратную сторону тремя разными проверками в двух файлах; следующий слот с таким же правилом пойдёт копипастой — стоит вынести в один предикат рядом с `isActiveForType`.
- **Язык виден только владельцу.** `MegumiTongueStatePayload` и `TongueClientFx` адресованы локальному игроку: соседи по серверу языка не увидят вообще. Если это осознанное ограничение — стоит зафиксировать в KNOWN_ISSUES; если нет — payload понадобится owner-uuid и вещание по радиусу.

## Вердикт

**Request changes** по существу (PR уже вмержен — читать как fast-follow список; замечу для честности: часть пунктов выше по стеку уже закрыта — reconcile сирот и предикат коллизии якоря — это подтверждает, что находки реальные, а не вкусовщина).

Порядок действий:
1. Якорь языка: проверка collision-shape вместо `isSolid()` + GameTest на заборе/плите.
2. Маркер-сирота: reconcile на JOIN/respawn — снять оба маркера при отсутствии записи в `PARTIALS`; желательно тест на «эффект есть — записи нет».
3. Координатор: LOS-матрица на каденции скана или кэш вердиктов на пару (body, candidate).
4. Мёртвый код: DOGS-арм SwapPolicy, lang-ключ swap, висячий комментарий профиля.
