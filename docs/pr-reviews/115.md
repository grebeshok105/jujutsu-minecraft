## Сводка

Клиентский quick-selector Мегуми: hold G открывает стрип без паузы, tap циклит выбор, клик шлёт C2S `ShikigamiSelect`, сервер отвечает S2C-снапшотом `ShikigamiState` (per-slot состояния + дедлайны, ребейз на клиентские часы). +3912/−14 по 56 файлам. Риск: **Medium** — сетевой код и жест ввода имеют реальные edge-кейсы; при этом все найденные серьёзные проблемы уже закрыты интеграционным мерджем #117/#118 на `main` (проверено: единый `MegumiSummonCooldowns`, `packs()` вместо `pack()`, partial-lock в `selectShikigami`, `isDefault()`-only fallback, push при отказе).

## Сильные стороны

- Vessel-seam соблюдён по образцу: пакеты намеренно «немые» (id-строка + параллельные массивы), приёмник диспетчит через `JujutsuCharacters.of(player)`, дефолт `selectShikigami → false`; на клиенте `hasQuickSelector()`/`openQuickSelector()` + маркер `QuickSelectorScreen` — shared-код нигде не называет сосуд.
- Жест tap/hold вынесен в чистый `SelectorGesture` и покрыт JUnit по тикам; edge-кейсы (суб-тиковый тап через clickCount, экран посреди холда = отмена пресса, `KeyMapping.setAll()` после `releaseAll`) продуманы и задокументированы.
- Клиентская read-модель честная: optimistic только `selected`, остальное из снапшота; COOLDOWN самолечится по дедлайну — сервер не обязан пушить истечение.
- `ShikigamiStatePayload`: bounded read (`MAX_SLOTS`, `MAX_ID_LENGTH`), defensive copy массивов в compact-конструкторе, дедлайны против `gameTime` сервера — хорошая wire-гигиена.
- PiP-рендер с пином settled-позы и ручной инъекцией `PACKED_LIGHT` — обоснованный workaround реального крэша GeckoLib, задокументирован.
- GameTest'ы идут через продакшн-шов `JujutsuCharacters.of(player).selectShikigami(...)`, а не через тестовые сеттеры; assert'ят живость пака, а не только флаг выбора.
- Документация, KNOWN_ISSUES и codex обновлены в том же PR — сужения (`LOCKED`/`DESTROYED`/`TEMPORARY` без продьюсера, один пак, бесплатный выбор) честно записаны.

## Проблемы

1. **[major]** Дублирующийся per-type ledger `MegumiShikigamiCooldowns` зеркалит `CharacterAbilityCooldowns` руками на каждом сайте зарядки (инлайн в `MegumiShikigamiRuntime`). Любой будущий путь списания пака, забывший одну из записей, даст селектор, который врёт READY при живом запрете PRIMARY. На main уже объединено в `MegumiSummonCooldowns` — правило на будущее: селектор читает тот же источник дедлайнов, что блокирует summon.
2. **[major]** `MegumiShikigamiSync` выводит `SUMMONED` из единственного `pack()` + boolean для собак — структурно один пак на шикигами (инлайн). Провод это уже умеет, продьюсер — нет; на main исправлено через `packs()`.
3. **[minor]** `selectShikigami` при отказе возвращает `false` без ответного пуша — optimistic `markSelected` на клиенте остаётся висеть до следующего не связанного с кликом снапшота (инлайн). На main отказ уже пушит.
4. **[minor]** Провод нейтрален по форме, но не по имени: `shikigami_select`/`shikigami_state`, `selectShikigami(player, shikigamiId)` — лексика Мегуми в общем seam (инлайн).
5. **[minor]** `ShikigamiStatePayload.write` не проверяет `MAX_SLOTS` — асимметрия bound'а (инлайн).
6. **[minor]** Переиспользуемый стек селектора (layout/motion/theme/state/feedback) параметризован `MegumiShikigami` и живёт в `megumi/selector/` (инлайн) — второй потребитель потребует генерализации или форка.
7. **[nit]** `ShikigamiSelectorState.flags()` аллоцирует `LinkedHashSet` на слот на кадр (инлайн); `byIdOrDefault` молча сворачивает неизвестный id в `DOGS` (инлайн); `MegumiShikigamiSelection.cycle()` теперь зовут только тесты; двойной push при заходе (JOIN + `onSelected`); `/jujutsu_debug shikigami_selector` доступен в проде — прецедент `domain_sphere` есть, но команда-имя сосуда в общем debug-неймспейсе.
8. **[вне диффа, контекст]** `JujutsuKeybinds.isActive` (предсуществующий хелпер, сам автор подсветил): physical fallback при `isUnbound()` — «Unbound» в настройках не отключает физическую G. На main уже исправлено до `isDefault()`-only; стоит занести паттерн в KNOWN_ISSUES как пример ловушки.

## Архитектурные риски на будущее

- **Зеркалирование ledger'ов — главный риск этого диффа.** Две записи об одном восстановлении (slot-keyed и type-keyed) расходятся на первом же новом пути списания; интеграция с #117 это уже показала и решила. Принцип, который стоит зафиксировать: readiness-UI читает источник, который реально блокирует действие, — не параллельный журнал.
- **`MegumiShikigamiSync` — единственная точка сборки снапшота, и она горячая.** Переход на multi-pack уже потребовал переписать её; когда появятся продьюсеры для `LOCKED`/`DESTROYED`/`TEMPORARY` (они уже в протоколе и в разметке маркеров), вся правда о доступности окажется размазана по рантаймам — сборка должна оставаться единственной и исчерпывающей, иначе полоса начнёт показывать частичные состояния.
- **Нейминг нейтрального канала.** `shikigami_*` в `jujutsu.mod.network` и параметр `shikigamiId` в `CharacterDefinition` — второй сосуд с ростером унаследует чужой термин или сломает wire при переименовании. Переименовать в `roster_*` дешевле до появления второго потребителя.
- **Стек селектора внутри vessel-пакета.** `SelectorMotion`/`ShikigamiSelectorLayout`/`ShikigamiSelectorState`/`SelectorTheme`/`SelectorFeedback` — фактически generic UI-машинерия (~1.5k строк), жёстко типизированная `MegumiShikigami`. Для первого среза оправдано, но это известная точка расширения — занести в codex.
- **Одна физическая клавиша — один input-контракт.** Столкновение default-G с жестом #117 (press/release у partial) показало: `JujutsuKeybinds` уже держит несколько state-машин (tap/hold, press/release, double-click, hold-charge) — следующий жест стоит регистрировать через общий реестр, а не добавлять четвёртую ad-hoc FSM в один файл.
- **Статический клок `MegumiShikigamiCooldowns.observe` подпитывался чужим тиком** — неявный инвариант «runtime обязана тикать, иначе ledger молча недозарядит». На main заменён, но паттерн хрупок сам по себе: часы лучше протягивать параметром.
