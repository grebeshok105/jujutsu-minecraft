## Сводка

Батч фиксов хвата (issues #90/#92): «одна жертва — один держатель» для раннера и жабы, release при смерти/дисконнекте жертвы, коллизионная проба якоря, LoS-гейт перенесён с владельца на жабу, точечное снятие «своей» Slowness, очистка `CARRIED` на `SERVER_STOPPING`, `ABILITY_RELEASE` со всех путей `end()`, правка KNOWN_ISSUES + 5 новых GameTest-оракулов. Риск: Medium — серверный контрольный путь и сетевые события, но каждый фикс закрыт сценарием с красным пруфом; оставшиеся проблемы угловые.

## Сильные стороны

- Фиксы лечат корень, а не симптом: ре-чек eligibility на тике коммита закрывает гонку select→grab; явный `release` при смерти жертвы через `resolveHeld` вместо «маркер сгниёт сам»; broadcast в `end()` вместо обвязки всех точек вызова.
- Контракты отказа продуманы: у раннера отказ до `tryStart` не жжёт кулдаун, у жабы отказ на коммите осознанно армирует его — зафиксировано тестом, не случайность.
- KNOWN_ISSUES приведён в соответствие с реальным кодом `HoldInputMixin` — редкая дисциплина doc-fix в багфикс-батче.
- Тесты с ред-пруфами в javadoc и мутационной проверкой; premise-ассерты доказывают именно тестируемый гейт (LoS владельца реально разрезана стеной).
- Границы соблюдены: вся логика в `src/main`, используются shared `HoldSupport`/`CombatTags`/`isEligibleTarget`, hard-coding чужого сосуда отсутствует.

## Проблемы

1. **[major]** Раннер не отклоняет пассажиров — правило «жертва в лодке ускользает честно» применено только у жабы; `RunnerEffect.start` примет игрока на транспорте (инлайн).
2. **[minor]** Дублирующий `ABILITY_RELEASE` на expiry-пути: `expireWindow` для GRAB_RUNNER проходит общий `occupiesAttackClip`-блок и шлёт RELEASE поверх того, что теперь шлёт `end()` (инлайн).
3. **[major]** Коллизионная проба якоря живёт в `MegumiToadBrain`, хотя pin — это `HoldSupport`: у раннера та же сцена «жертва в стене» не прикрыта; фоллбэк «к лапам жабы» не гарантирует свободу для жертвы с более широким боксом (инлайн).
4. **[minor]** Эвристика «своей» Slowness (amplifier+duration) не переживает чужой длинный эффект — merge рефрешей смешивает владение (инлайн).
5. **[minor]** Отказ по `isHeld`/`isPassenger` случается только на коммите: sic по уже занятой жертве проигрывает виндап со звуком и tongue-куэ и жжёт кулдаун (инлайн).
6. **[minor]** Отладочный след в GameTest: `Component.literal("diag …")`-ассерты, FQN-типы вместо импортов, `freezeDiag`-стейт (инлайн).
7. [nit] `resolveHeld` возвращает null для жертвы, ушедшей из уровня (смена измерения/удаление до выхода) — `clearGrab` без явного `release`; маркер сгниёт сам за ≤10 тиков, но это второй путь «забытого отпускания» — стоит хотя бы отметить в KNOWN_ISSUES.
8. [nit] `isRunnerVictim(victim)` в новой проверке избыточен — carried-жертва уже несёт GRIPPED; два параллельных ответа на «пиннута ли жертва» (`CARRIED` и маркер) — исходная почва бага, который тут чинится.

## Архитектурные риски на будущее

- «Один держатель» держится на булевом флаге без идентичности держателя: GRIPPED-маркер отвечает «занят ли», но не «кем занят», а `CARRIED` — параллельное множество тех же жертв. Каждый будущий держатель (следующий шикигами, новый захват) обязан помнить и входной `isHeld`-гейт, и «не снимай чужой» release — инвариант распределён по точкам вызова. Структурный шаг: таблица holder→victim внутри shared hold-механизма, чтобы `hold(holder, victim)` сам отказывал при занятой жертве — тогда запрет второго захвата становится свойством механизма, а не конвенцией вызывающих.
- Коллизионная политика пина — часть контракта `HoldSupport`, а не сосуда: сейчас два держателя с разной защитой от стены (жаба прикрыта, раннер — нет). При третьем держателе это станет копипастой проб и фоллбэков.
- Асимметрия контрактов отказа: раннер отказывает бесплатно, жаба — с вооружённым кулдауном. Разумно по отдельности, но как правило нигде не записано — следующий держатель выберет случайно.
- «Held»-состояние — это моб-эффект: `isHeld` читает `hasEffect(GRIPPED)`, т.е. любой источник этого эффекта (зелье, команда, будущая механика) будет участвовать в отказах захватов; тест уже эксплуатирует это, ставя маркер «голым» `applyHold` как суррогат чужого захвата.
- Закрытие клип-события размазано: WINDUP шлёт `start()`, RELEASE теперь шлют `end()`, общий клause `expireWindow` и hit-пути других эффектов — при следующем эффекте легко получить дубль или пропуск.
